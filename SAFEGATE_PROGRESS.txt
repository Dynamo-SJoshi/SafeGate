Important learnings
-------------------

1. Git tracks changes locally, GitHub stores them online.
2. Git workflow for this project:
   - make a small change
   - test it
   - commit it
   - push it to GitHub
3. A Python virtual environment (.venv) is a private Python space for SafeGate only.
4. pip installs Python packages.
5. When .venv is active, pip installs packages only for this project.
6. PostgreSQL can be installed on D drive while the project lives on C drive.
7. The frontend and backend are separate apps and should be run in separate terminals.
8. Next.js is the frontend framework currently being used.
9. FastAPI is the backend framework currently being used.


How to start the backend
------------------------

Folder:
   C:\Users\DELL\Downloads\SafeGate

Steps in Command Prompt:

1. Create the virtual environment:
   python -m venv .venv

2. Activate it:
   .venv\Scripts\activate

3. Install backend dependencies:
   pip install -r backend\requirements.txt

4. Start the backend server:
   uvicorn backend.app.main:app --reload --host 127.0.0.1 --port 8000

5. Test the backend:
   http://127.0.0.1:8000/health

Expected response:
   {"status":"ok","service":"safegate-api"}

How the frontend connects to the backend
---------------------------------------

1. Browser opens the Next.js frontend on port 3000.
2. The frontend calls its own route:
   /api/health
3. That route calls the FastAPI backend:
   http://127.0.0.1:8000/health
4. The frontend shows backend status as online when the backend responds correctly.

Security / design decisions
---------------------------

1. Treat all uploads as hostile.
2. Prefer static analysis before dynamic execution.
3. Do not run unknown files on the host.
4. Use temporary data and cleanup later.
5. Keep the MVP simple before adding sandbox execution and AI summaries.

PostgreSQL integration update
-----------------------------

Current work:

- Added a PostgreSQL persistence layer for upload metadata.
- Added a table bootstrap step for the `uploads` table.
- Added a `DATABASE_URL` template in `backend/.env.example`.

Important note:

- The backend now expects a valid PostgreSQL connection string in `DATABASE_URL`.
- Example format:
  - `postgresql://postgres:YOUR_PASSWORD@localhost:5432/postgres`

What this enables:

- each upload can be written to PostgreSQL
- SafeGate can later query upload history and analysis state
- the app is moving from temporary-only storage toward real persistence

SSRF-safe URL analysis update
-----------------------------

Current work:

- Added a backend `/analyze-url` endpoint.
- Added SSRF protection rules for SafeGate link analysis.
- Added URL fetching limits, redirect limits, and private-address blocking.
- Switched the main frontend action to paste a download link first.
- Kept file upload as a fallback action.

What SSRF protection blocks:

- `localhost`
- private IP ranges
- link-local addresses
- redirect chains that try to move into blocked targets
- non-http(s) URLs

Why this matters:

- SafeGate can now move toward its real use case: inspecting links before files are downloaded locally.
- The backend is protected from being tricked into fetching internal or dangerous addresses.


Steps to Push items in GITHUB
------------------------------

1.Navigate to your folder:Open your terminal or command prompt.Use the cd (change directory) command to go to the folder where your text file is saved:
  Bash   cd path/to/your/folder
2.Stage the file:Tells Git to track this specific file.Add your text file to the staging area. Replace filename.txt with your actual file's name:
  Bash   git add filename.txt(or any other particular file)
(Tip: If you want to add every changed file in the folder, use git add . instead).
3.Commit the change:Saves a local snapshot.Package your staged file into a commit with a brief, descriptive message:
  Bash   git commit -m "Add my text file"
4.Push to the repository:Uploads the commit to the remote server.Send your committed file to the remote repository. Assuming your remote is named origin and your primary branch is main:
  Bash   git push origin main
